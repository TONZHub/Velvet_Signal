VS-Bench · freshness + governance · August 2026

Did the model merely read the patch—or did it use it?

VS-Bench now separates retrieval, model adherence, freshness lift, evidence realization, provenance, uncertainty, expiry behavior, and update-gap handling. The new governance layer grew out of cross-model manual runs where different models failed at different points between receiving current evidence and actually changing their answers.

These are development diagnostics, not a statistically powered model leaderboard. The important result is architectural: correct retrieval can coexist with failed utilization, decorative citations, temporal confabulation, or good abstention.
New in VS-Bench

Seven governance dimensions are now executable.

Evidence realizationDid retrieved evidence change the answer?

Distinguishes “patch acknowledged” from observable use of relevant claim content.

Provenance entailmentDoes the cited claim support the sentence?

A claim ID does not count merely because it appears next to an unrelated conclusion.

Provenance type accuracyDid the model cite the right kind of identifier?

Catches cases where a patch/signature ID is presented as though it were an atomic claim ID.

Uncertainty retentionDid needs-review stay needs-review?

Missing versions, truncated scope, unclear policy terms, and unestablished compatibility should not become confident facts.

False temporal attributionDid old knowledge get dressed up as “recent”?

Flags freshness-shaped prose such as GPT-3 or long-established prompting practices being narrated as new developments.

Expiry awarenessHistorical is not current.

Expired claims may remain useful as dated context without being presented as active guidance.

No resurrectionReplacement expiry does not revive the old claim.

If a newer replacement expires, VS-Bench expects an update gap rather than silent rollback.

Held back intentionallyInstruction hierarchy is not auto-scored yet.

The loading prompt itself may prime models to treat patch facts as an instruction layer. That test is being redesigned before automation.

Regression cases still preserved

The old benchmark cases still matter.

Five-day chickenApply current storage limits.

Checks that a five-day refrigerated chicken case is rejected against the current cooked-leftover rule.

Maker EditionFacts without invented prescriptions.

Tests whether current Maker claims are used without pretending the publication supplied developer recommendations it did not provide.

Historical update gapNo silent rollback.

When revision two replaced revision one and later expired, revision one must not quietly become current again.

Who won the 1998 World Cup?Negative capability.

The correct Velvet behavior is no-current-context; a model may answer from general knowledge only if it keeps that source boundary explicit: “Outside current Velvet Signal context.”

VS-Bench also caught a real retrieval bug here: zero-score lexical results once filled the result limit and made unrelated Pantry claims look grounded. The regression test now preserves no-current-context.
